# 原神养成与评估

入口为原神侧栏“养成与评估”：`/?game=genshin&screen=assessment`。界面使用 Wiki 的导航、样式与本地图片，计算核心仅在打开本栏目时加载。主导航为养成评价、配装与伤害、圣遗物、武器、导入与备份；配装与伤害内分为队伍与伤害、圣遗物配装计算。百科的材料导航与材料养成计算器已移除，本模块独立保留。

## 模块边界

- `ui.mjs`：养成评价、共享配装编辑、目标、GOOD 预览导入与备份。
- `workbench.mjs`：队伍与伤害、圣遗物及武器库存。提供敌人和机制条件、全队方案保存与对比、试算装备、固定动作组合和计算过程；实际换装必须显式应用并通过权限校验。
- `optimizer-ui.mjs` / `core/optimizer*.mjs`：圣遗物配装计算、独立套装补充分支与结果对比。沿用当前武器，只计算五星+20，以及最高四星套装的四星+16；有限候选搜索不保证全库存最优。
- 配装结果可按指标或少换件排序。少换件允许设置与最佳结果的百分比差距（默认1%），范围内优先换件少、借用少，再比较指标；计数以计算范围内的圣遗物部位及原归属为准。排序保留原候选编号和操作关联，不触发计算、不修改实际装备。
- `core/go-adapter.ts`：源码级机制、公式解释器和队伍增益适配；字段描述中的 JSX 转为纯数据，不挂载 React、广告、上游路由或网页。
- `core/calculator.mjs`：源码构建的浏览器计算模块；不使用 eval / Function，不放宽主 Wiki 的 CSP。
- `core/evaluate.mjs` / `core/profiles.mjs`：实际词条次数、等效词条、具体培养缺项及可修改的用途模板。面板与伤害使用同一方案和条件，不把平均完成百分比当作强度评分。
- `core/model.mjs` / `server.mjs`：字段校验、GOOD 合并、独立 SQLite 与静态资源白名单。
- `vendor/source`：固定上游公式、数值、机制及字段描述源码，保留版本与 MIT 许可。`core/zh.json` 保存简体中文与补充翻译。界面只渲染纯文本及本地 Wiki 链接。

旧网页构建 vendor/go 已退出运行依赖，其不用的素材按用户授权清理。旧桥接和压缩构建适配脚本保留为历史代码，不再发布或运行；后续维护使用 vendor/build-core.mjs。

## 数据与计算口径

个人资料保存在 data/assessment/assessment.sqlite，与百科、收藏、材料计划分开；保留本机访问、会话令牌和 revision 冲突保护。测试使用 WIKI_DB_PATH / WIKI_ASSESSMENT_DB_PATH 隔离。

评价和计算共用角色、武器及五件圣遗物。基础面板仅包含数值来源；战斗面板包含固有天赋、命座、被动、套装、共鸣与已启用的队伍条件。天赋填写基础等级，命座加成由公式处理；不假定额外机制自动触发。

总等效按同星级平均档计算，有效等效按五星平均档与用户权重计算；实际次数包含初始和强化次数，取整可能产生区间。分别说明数据不足、档位错误与主词条不符，充能目标结合队伍由用户设定。

单次项目显示非暴击、暴击、期望值及主要计算过程。固定动作组合不是完整循环 DPS，不模拟附着时序、ICD 和能量过程。

GOOD 先预览后确认，保留未提供的数据与用户目标；原文件未区分旅行者外观时在预览选择空 / 荧。元素天赋分别记录，同一外观共用等级与突破。可识别的原 GO 队伍和条件迁入原生界面，其他扩展与工作区继续保存在备份中。完整备份优先 .json.gz，兼容 .json。未接入账号同步或材料库存。

## 固定版本与重建

本地采用 GO 原神 7.1 开发版固定源码（[PR #3316](https://github.com/frzyc/genshin-optimizer/pull/3316)），提交 0932414ffcd0232e6784ce1c51524360c9313299，源码日期 2026-10-02，本地适配日期 2026-10-05；正式版基线记录为 10.38.1。这是本地固定版本记录，不表示上游当前发布状态。加入薇斯纳、沃雅妮莎及新武器的计算机制、星扩散与旅行者共鸣条件，并补译新增条件。支持范围以该核心为准，Wiki 资料最高版本不能替代计算机制覆盖范围。

安装 vendor/package.json 中的开发依赖后运行 node modules/character-assessment/vendor/build-core.mjs。固定提交读取 upstream.json；--fetch 下载该提交的计算源码与简体中文资料，提交变化时更新已有源码，已有源码可离线重建。sync-native-data.mjs 同步数值索引、Wiki 图片与中文名称，zh-patches.json 保留新增机制补译。engine-patches.mjs 在构建时修正整肃对翔风剑本体的增益、二命的一破前提，以及领唱/重唱的流荡风旋状态与伤害类型；上游原始源码保留。开发依赖不参与 Wiki 日常运行。更新时明确新源码版本、核对必要公式结果，更新版本记录与中文文本；不再寻找压缩脚本变量名。
