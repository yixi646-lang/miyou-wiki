# Wiki 本地发布与更新管理指南

本指南适用于分享给朋友的 Windows x64 便携版。更新通过更新包自己的安装程序完成；**功能回退仅限维护者本机，分享版不提供回退入口或版本备份**。网页只显示版本号。首次正式发布为 **Wiki 1.0.0 / R000001**。

## 版本与发布批次

- 软件版本：增加功能时提高主、次版本，例如 1.0.0 → 1.1.0。修复、样式调整及游戏资料增加默认保持原版本；用户明确要求修订版本时可保持主、次版本并提高第三段，例如 1.1.0 → 1.1.1，按 `fix` 发布，不新建功能回退点。
- 发布批次：每次正式分享递增，例如 R000001、R000002。即使功能版本相同，也能区分朋友已安装的资料和修复。
- 发布类别：`fix`（修复 / 样式）、`content`（游戏资料）、`feature`（新增功能）。类别不会筛掉其他改动；包中仍包含发布基准以来全部有效变化。
- 无需维护 SHA256 清单。工具使用本地 Git 保存发布快照，朋友不需要 Git，不连接 GitHub。

## 维护者工作流程

1. 平时继续用 Codex 修改正式项目，不必逐次列出文件或手动提交。
2. 确认本轮功能、资料及必要检查完成，关闭正在编辑的文件。生成器在独立临时目录收集当前发布范围，数据库仅读取。
3. 生成器重建立绘索引、同步计算资料；计算源码发生变化时重建计算核心。新文件、修改与删除均自动收集，发现未知顶层目录时停止并要求调整发布配置，避免静默遗漏。
4. 生成草稿包，检查输出摘要。草稿和失败打包不会推进“上次正式发布”。
5. 将已检查的草稿正式登记，再把 ZIP 发给朋友。只有正式登记才增加发布批次，并更新项目的 `release.json`。

常用命令（在 Wiki 目录执行，开发电脑需要 Node.js 24 和 Git）：

```powershell
# 修复 / 样式；功能版本不变
node scripts/release-wiki.mjs build --kind=fix
# 用户明确要求修订版本时；不建立新功能回退点
node scripts/release-wiki.mjs build --kind=fix --version=1.1.1 --from=R000004
# 新增游戏资料；功能版本不变
node scripts/release-wiki.mjs build --kind=content
# 新功能；升版本
node scripts/release-wiki.mjs build --kind=feature --version=1.1.0
# 为停在较早批次的朋友生成累计更新包
node scripts/release-wiki.mjs build --kind=content --from=R000001
# 正式登记已生成的草稿（使用 build 输出的草稿编号）
node scripts/release-wiki.mjs publish --draft=草稿编号
# 查看正式发布记录
node scripts/release-wiki.mjs list
```

首次完整分享包使用 `build --kind=full --version=1.0.0 --publish`。今后也可使用 `--full` 同时提供当前批次的完整包，例如 `build --kind=feature --version=1.1.0 --from=R000003 --full`。更新包和完整包从同一发布快照生成、使用相同批次。输出 ZIP 按 `release-config.json` 的 `outputDirectory` 放在“各种包体”目录；已有同名 ZIP 不覆盖。

发布详情保存在 `docs/releases/软件版本-发布批次.txt`，例如 `1.1.0-R000004.txt`。生成器随本次快照采集，并作为更新包与完整包根目录的 `版本更新详情.txt`；使用教程位于完整包的 Wiki 目录，更新包根目录也提供一份。详情必须针对本次真实变化，不把已在基准包内的功能写成新增。

更新包同时提供 `更新文件清单.txt`，从两个发布快照比较自动列出全部新增、修改、删除文件及公共条目变化。正式登记前核对包内清单与快照差异，发布范围由整个目录及公共数据库采集，不按本轮对话、文件时间或手写功能清单筛选。

维护电脑的构建依赖已放在 `.release-manager/build-tools`。如果以后需要重新安装，只在该目录安装固定版本，不改全局环境：

```powershell
npm install --prefix .release-manager/build-tools --no-audit --no-fund esbuild@0.25.10 fflate@0.8.3
```

朋友只需要完整包自带的运行时，不安装这些开发依赖。固定运行时变化时使用 `build --kind=full`，本版不生成覆盖正在运行的 node.exe 的增量包。

发布过程中不要让另一个 Codex 任务同时修改源码或正式资料。生成器锁定发布任务，并检查采集前后文件内容及数据库导出一致，变化时停止，不把混合状态登记为正式发布。

## 独立百科资料合并

正式资料库是当前百科条目的来源。发布工具从 SQLite 的一致性只读快照导出公共条目，保留条目内容、修订号与真实更新时间，不导出收藏、材料库存、计划和养成评估账号。

完整包的初始化资料由本次公共导出生成，不使用过时的初始化 JSON 覆盖正式资料。更新包只携带新增 / 变化条目及删除清单，安装器事务内合并，不替换朋友的 SQLite 文件。

合并采用“上次官方内容 / 朋友当前内容 / 新官方内容”三方比较：

- 朋友没有编辑的字段更新到新内容。
- 朋友编辑而发布者没改的字段保留。
- 双方同时修改同一字段且不同，保留朋友的值，把冲突写入 `.updates/conflicts/`，供以后人工处理。数组作为整体处理。
- 朋友自建条目不删除。官方撤回条目如存在本地修改或仍被收藏 / 计划引用，也保留并记录原因。
- 收藏、材料库存、养成计划及 `data/assessment` 下的账号、装备、目标、队伍、原始扫描与恢复记录不参与发布和合并。

更新器同时更新官方初始化资料，防止旧条目在下次启动时被重新补入。来源快照、成长资料、版本档案和图片按文件差异更新。

## 朋友安装更新

1. 关闭全部 Wiki 页面，等待约 15 秒，让后台服务退出；扫描器也应关闭。
2. 将更新 ZIP 解压到独立目录，不直接解压覆盖现有 Wiki。
3. 双击更新包自己的 `安装更新.vbs` 打开窗口式向导；`安装更新.cmd` 打开同一窗口。可选择现有 Wiki 文件夹或直接选择 `启动百科.vbs`，外层目录内只有一份 Wiki 时自动定位。安装程序、合并代码均在更新包中。
4. 向导显示当前 / 目标版本、目录检查结果和需处理的文件数量。检查通过后点击“开始更新”，显示进度与当前阶段；成功、失败或已经是目标版本均明确显示，并保留结果窗口，可启动 Wiki、打开目录及查看日志。

若只修订安装器而不改变已发布的内容，可执行 `node scripts/release-wiki.mjs repack-installer --package=Wiki-1.0.1-更新包.zip`。工具保留原清单和 payload，仅重做安装程序及包内安装帮助，生成新的“窗口安装版”ZIP；不改变软件版本、发布批次或正式比较基准，也不覆盖旧包。安装日志在解压后的更新包 `安装日志/` 中。

起始批次不匹配时拒绝安装；请索取对应起点的累计更新包。尚无 `release.json` 和 `.updates/installed.json` 的旧分享包不能猜测基准，首次使用本次 1.0.0 完整包建立新目录；个人资料通过各模块的备份导入迁移，不直接覆盖旧目录。

## 功能回退

正式登记新增功能版本时，在维护者本机保存升级前发布快照的引用作为回退点。旧文件和旧公共条目已保存在本地 Git 中，未变化内容复用，不再复制整份目录。修复 / 样式 / 内容更新不建立独立功能回退点，也不移动现有回退目标；此后回退会自动比较当前状态与该固定目标。

在维护者本机关闭 Wiki 后运行 `回退Wiki.cmd`，输入 YES 确认。回退会恢复到功能升级前的公共代码及资料状态，包括此后发布的公共内容和修复；它不是只移除某个菜单。个人收藏、库存、计划及评估账号保留。回退时也采用三方合并，保留未发布的个人百科编辑并报告冲突。回退不删除正式发布历史，之后发布仍按最新正式批次递增。

本机保存最近一次功能升级的回退目标；旧发布快照继续保留，工具不自动清理历史。朋友安装更新不创建功能版本备份；只保留安装期间的临时事务恢复文件，成功后清理，失败恢复更新前状态，进程中断后下次操作先恢复未完成事务。

更新安装器不替换或操作评估账号数据库。1.0.1 的账号模块首次读取时追加账号类型表，原有表和资料保留；旧程序忽略新增表。未来若改变原有字段或资料格式，须先处理迁移与兼容，不能把代码文件恢复等同于个人数据回退。

## 目录与维护约定

- `.release-manager/repository.git`：仅维护者使用的本地发布快照。必须保留，丢失后不能生成可靠累计差异。
- `.release-manager/state.json`、`drafts/`：正式发布与草稿记录。不要手动改编号或删除上次基准。需要再发已经发布的相同批次时，直接使用已有 ZIP；再次 build 会产生新批次。
- `.release-manager/runtime`：固定 Node.js 运行时及许可证缓存；不要求朋友安装 Node。
- `.release-manager/build-tools`：仅开发时使用的构建依赖，不进入分享包。
- `.release-manager/local-rollback.json`：维护者本机的功能回退目标，不进入分享包。
- `.updates/`：朋友安装状态、官方条目基准及冲突。应随 Wiki 一起移动，不含功能回退点。
- `release.json`：功能版本、发布批次及本次发布时间。游戏资料的更新时间仍取真实来源，不用发布时间冒充。
- `release-config.json`：发布范围与明确排除项。新增模块、根目录或资料目录时先更新配置。

根目录旧 ZIP、历史备份、日志、测试目录、预览、浏览器配置和 Scanner 的个人 GOOD 导出不进入分享包。扫描器仅发布程序、识别资料及许可，不发布个人扫描；指定的扫描器入口在发布副本转换为相对路径快捷方式，安装时按接收者目录设置，不发布其他机器快捷方式。

后续 Codex 维护须读取本指南。普通调整不推进发布基准；只有用户要求正式发布时执行登记。所有发布范围内最终有效的改动都由整个快照比较收集，不依靠本轮对话记忆。

构建工具的安装方法参考 [esbuild 官方文档](https://esbuild.github.io/getting-started/#install-esbuild)。本项目固定构建依赖版本；完整包无需 npm install。Node.js 运行时升级需提供新的完整包，本版增量安装器不在自身运行时覆盖 node.exe。
